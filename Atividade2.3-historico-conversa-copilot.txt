O arquivo DEVE ter exatamente estas seções:

## 1. Contexto
Quando esta skill se aplica (frase-ativação) e por que existe.

## 2. Regras prescritivas
Lista de regras no formato DEVE / NÃO DEVE. Cada regra em uma linha. Inclua ao menos:
- Uso de strict mode (sem implicit any, sem type assertions desnecessárias)
- Convenção de imports (named exports preferidos, default export apenas para módulo principal)
- Convenção de nomenclatura (interfaces com I prefix ou não, types vs interfaces, enums)
- Uso de readonly em campos que não mudam
- Tratamento de nullability (undefined vs null, Optional Chaining, Nullish Coalescing)
- Proibição explícita de console.log (usar pino)
- Uso de .js nas extensões de import (obrigatório para ESM no Azure Functions v4)

## 3. Exemplos de código (DO / DON'T)
Mínimo 4 pares DO/DON'T com código TypeScript real. Cada par deve mostrar um anti-padrão que o Copilot geraria sem esta skill vs o padrão correto do projeto. Use comentários explicando POR QUE o DON'T é errado neste projeto especificamente.

Exemplos que DEVEM aparecer:
- DO/DON'T: importar com .js vs sem extensão
- DO/DON'T: usar pino vs console.log
- DO/DON'T: readonly em interfaces vs campos mutáveis
- DO/DON'T: type assertion segura vs casting com as

## 4. Anti-padrões específicos de IA
Lista de anti-padrões que o GitHub Copilot e Claude especificamente geram neste projeto sem esta skill. Para cada um: nome do anti-padrão, exemplo de código errado que a IA geraria, por que é um problema neste projeto.

## 5. Dependências
Outras skills que devem ser lidas junto com esta (ex: error-handling.md).
